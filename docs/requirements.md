# 局域网群聊共享 — 详细需求

## 1. 背景与目标

同一局域网内，多台设备通过浏览器打开同一个网页，即自动进入同一个群聊，共享文字、图片和文件。

每台运行服务的设备只需启动一次群聊服务器；服务器负责托管页面和转发 WebRTC 信令，**服务器本身不是群成员**。每个打开页面的浏览器客户端才是独立成员。

## 2. 范围与非目标

### 2.1 范围内
- 打开网页即入群，无需选择房间或手动添加设备。
- 每个浏览器客户端独立身份与昵称，刷新后保持不变。
- 内容（文字/图片/文件）在浏览器之间通过 WebRTC DataChannel 直连传输，不经过服务器中转或保存。
- 单一共享群聊，广播式收发；中文界面，桌面与手机适配。

### 2.2 非目标
- 账号体系、登录鉴权、私聊、@成员、已读回执、群聊房间。
- 跨公网传输与 NAT 穿透；历史消息与文件持久化；断点续传。
- 多语言；大规模成员数承诺（目标 ≤ 8 个浏览器客户端）。

## 3. 术语
- **成员（client）**：一个打开页面的浏览器客户端，由 localStorage 中的 UUID 标识，可独立修改昵称。
- **群聊服务器（agent）**：Node.js 进程，托管静态页面并提供 WebSocket 信令端点 `/browser`；不持有身份，不保存内容。
- **信令（signaling）**：建立 WebRTC 连接时交换的 SDP/ICE 消息，经服务器按 `toClient` 转发。
- **消息（timeline item）**：群中一条文字/图片/文件记录，携带发送者 clientId 与昵称。

## 4. 总体架构

```
             ┌──────────── 群聊服务器（局域网一台设备） ────────────┐
             │  HTTP 静态页面 + WS /browser 信令中继               │
             └───────┬──────────────────────┬──────────────────────┘
                     │ WS                  │ WS
             ┌───────▼────────┐    ┌───────▼────────┐
             │ 浏览器成员 A    │    │ 浏览器成员 B    │
             └───────┬────────┘    └───────┬────────┘
                     └── WebRTC DataChannel 直传 ────┘
```

- 控制面：浏览器只与群聊服务器建立一条 WS，用于注册、成员上下线通知和信令转发。
- 数据面：成员之间全 mesh WebRTC DataChannel 直连，文字/图片/文件均走此通道。
- Cloudflare Pages 可分发同一份静态页面；页面需通过 `?agentWs=ws://<服务器IP>:3000/browser` 指向局域网信令服务器。

## 5. 运行模型

### 5.1 成员身份
- 浏览器首次打开页面时生成 UUID，存入 `localStorage`（`local-share.client-id`），刷新后保持不变。
- 默认昵称取自浏览器所在系统信息（如 Mac、Windows、Android、iPhone、iPad），由 `navigator.userAgent` / `userAgentData` 解析；用户可修改，存入 `localStorage`（`local-share.nickname`），不影响其他成员。
- 昵称变更由服务器广播给其他成员；历史消息保留发送当时的昵称。

### 5.2 启动
- 在局域网一台设备上运行 `npm run build && npm start`（默认端口 3000）。
- 其他设备浏览器访问 `http://<服务器IP>:3000`，打开即自动入群。
- 项目为单一包、单一服务器：`src/app/` 前端、`src/lib/` 共享逻辑、`src/server/` 服务端。`npm run dev` 先构建前端再由同一个服务器（默认 3000）托管页面与信令，全程只有一个服务进程与一个端口。

## 6. 功能需求

- **FR-1 入群**：浏览器连接 `/browser` 并上报 `clientId` 与 `nickname`，服务器返回当前成员列表，并通知其他成员。
- **FR-2 单一群组**：全网段只有一个群，所有连接的浏览器自动进入，无需选择。
- **FR-3 文字**：纯文本广播，最多 2000 字符，前端拦截超限。
- **FR-4 图片**：选择或拖入发送，单张 ≤ 20MB，接收后展示并可下载原图。
- **FR-5 文件**：选择或拖入发送，单文件 ≤ 100MB，接收后显示文件名与大小并可下载。
- **FR-6 界面**：消息气泡按时间正序排列，自己靠右、他人靠左，显示昵称、时间、传输状态；侧栏展示成员列表与昵称设置。
- **FR-7 传输反馈**：发送/接收进度条；传输中可取消；每个成员独立统计"已送达 x/y"。
- **FR-8 掉线重连**：浏览器 WS 断开后清除成员并关闭 DataChannel，2 秒后自动重连；离线期间内容不补发。
- **FR-9 昵称管理**：昵称属于浏览器本地，修改后写入 localStorage 并同步给群内其他成员。

## 7. 消息格式

### 7.1 浏览器 → 服务器（WS JSON）
```json
{ "t": "register", "clientId": "<uuid-v4>", "nickname": "<string>" }
{ "t": "signal", "toClient": "<uuid-v4>", "data": { "description": "...", "candidate": "..." } }
{ "t": "nickname", "nickname": "<string>" }
```

### 7.2 服务器 → 浏览器（WS JSON）
```json
{ "t": "init", "clients": [{ "clientId": "<uuid-v4>", "nickname": "<string>" }] }
{ "t": "client-online", "clientId": "<uuid-v4>", "nickname": "<string>" }
{ "t": "client-offline", "clientId": "<uuid-v4>" }
{ "t": "peer-nickname", "clientId": "<uuid-v4>", "nickname": "<string>" }
{ "t": "signal", "fromClient": "<uuid-v4>", "data": { "description": "...", "candidate": "..." } }
```

### 7.3 DataChannel 内容帧
- 控制帧：JSON，包含 `meta`（id/type/from/fromNickname/ts/size/chunks/text/fileName/mimeType）、`ack`、`cancel`、`nickname`。
- 数据帧：二进制，36 字节 id + 4 字节序号 + 分片负载（16KB/片）。

## 8. 接口约定

- 浏览器 WS 地址默认与页面同源：`ws(s)://<页面host>/browser`；页面从其他地址托管时可用 `?agentWs=` 覆盖。
- 服务器只按 `toClient` 转发信令，不解析 SDP，不保存任何消息或文件。
- 同一 `clientId` 重复连接时，旧连接被关闭，保证一个浏览器成员只有一个有效连接。

## 9. 非功能需求

- 规模：目标 ≤ 8 个成员，全 mesh 连接数按 O(n²) 增长。
- 可靠性：消息按 UUID 去重、按时间戳排序；错误有明确提示。
- 安全：开放局域网访问，无鉴权；WebRTC 通道具备 DTLS 加密。
- 兼容：支持 DataChannel 的现代浏览器；Node.js ≥ 20。

## 10. 验收标准

1. 两台设备浏览器打开同一页面地址，自动出现在彼此成员列表中。
2. 任一浏览器修改昵称，其他成员的界面同步更新，且各自昵称互不影响。
3. 文字、图片、文件发送后其他成员实时收到，排序正确且不重复。
4. 发送端显示进度与"已送达 x/y"，接收端可下载文件与原图。
5. 成员关闭页面后从列表移除；重新打开后自动恢复连接。
6. 服务器停止后成员界面显示断连并自动重试；服务器恢复后自动重新入群并恢复收发。

## 11. 已知限制

- 不保留历史：页面刷新或离开后，之前的消息不可见。
- 无鉴权，任何能访问页面的设备都可加入。
- 跨网段/公网传输需自行部署信令服务器并通过 `?agentWs` 指定。

## 12. 部署

- 静态导出：`npm run build`，产物在 `out/`。
- 局域网使用：`npm start` 在局域网一台设备启动服务器，其他设备访问 `http://<该设备IP>:3000`。
- Cloudflare Pages：推送 tag 时 GitHub Actions 构建并部署静态页面；页面通过 `?agentWs=ws://<局域网服务器IP>:3000/browser` 连接信令服务器。
